# Куди що вписувати (Monoclo Reports)

Паролів і токенів у цьому файлі **немає і не буде**. Секрети вписуєте тільки самі, тільки у «Властивості скрипта», нікому не надсилайте.

## Частина 1. Властивості скрипта (секрети й ID підключень)

**Де:** таблиця Monoclo Reports → **Розширення → Apps Script** → ліворуч шестерня ⚙️ **«Налаштування проєкту»** → внизу **«Властивості скрипта»** → **Редагувати властивості скрипта**.

Кожен рядок: ліворуч назва (**точно так**, великими літерами), праворуч значення. Після змін натисніть **«Зберегти властивості скрипта»**.

| Назва | Що вписати | Секрет? |
|---|---|---|
| `KEYCRM_API_BASE` | `https://openapi.keycrm.app/v1` | ні |
| `KEYCRM_API_KEY` | API-ключ KeyCRM (KeyCRM → Налаштування → API) | **так** |
| `META_ACCESS_TOKEN` | токен системного користувача Reports Bot (Business Settings → Системні користувачі → Reports Bot → Створити токен) | **так** |
| `META_AD_ACCOUNT_ID` | `1366087074297451,1368829087067672,960533087090531,1396469078723164` (чотири акаунти Mono Clo через кому) | ні |
| `META_API_VERSION` | те, що вже стоїть (наприклад `v26.0`), **не змінюйте** | ні |
| `TG_BOT_TOKEN` | токен бота від @BotFather | **так** |
| `TG_CHAT_ID` | `-5203041116` (група зі звітами) | ні |
| `TG_ALERT_CHAT_ID` | куди надсилати тривоги; порожньо = у ту саму групу | ні |
| `SHOPIFY_STORE_DOMAIN` | `ibvza0-1g.myshopify.com` | ні |
| `SHOPIFY_API_VERSION` | те, що вже стоїть, **не змінюйте** | ні |
| `SHOPIFY_CLIENT_ID` | Client ID застосунку Shopify (Dev Dashboard) | ні |
| `SHOPIFY_CLIENT_SECRET` | Client secret того ж застосунку | **так** |

Нічого більше в цьому розділі змінювати не треба. Властивості, які починаються з `state_` і `direct_cache_`, створює скрипт сам, їх **не чіпайте**.

> Токен Shopify (`shpat_…`), який було видно на скріншоті KeyCRM, треба перевипустити в Shopify. Новий вписується тільки у `SHOPIFY_CLIENT_SECRET` (або не потрібен, якщо Shopify-резерв вимкнено, див. нижче).

## Частина 2. Лист «Налаштування» (звичайні налаштування)

**Де:** таблиця Monoclo Reports → внизу вкладка **Налаштування**. Змінюєте **тільки стовпець B** (value). Стовпці A і C не чіпайте.

### Що зробити зараз

| Рядок (key) | Що вписати в B | Навіщо |
|---|---|---|
| `keycrm_source_other_ids` | `2,7,9,25,39,62,84,97,111,160,166,186,202,215,224,231,232,234,182,211` | Додано 182 («чердак дроп») і 211 («UGC»), щоб щодня не приходило попередження про невідоме джерело |
| `shopify_utm_fallback` | `FALSE` (рекомендовано) | Shopify на цьому магазині майже не віддає UTM; мітки беруться з коментаря KeyCRM. Вимкнення прискорює запуск |
| `keycrm_source_site_ids` | `212` | Є **два** однакові рядки з таким ключем (перший порожній). Залиште рядок зі значенням `212`, порожній видаліть |

### Цілі (ваші бізнес-рішення, поточні значення з ТЗ)

| Рядок (key) | Зараз | Що означає |
|---|---|---|
| `target_cpa_total` | `350` | ціль CPA Meta за CRM, грн |
| `target_cpa_site` | `400` | ціль CPA сайту за пікселем, грн |
| `target_roas` | `3` | мінімальний ROAS |
| `target_cost_per_conversation` | `30` | ціль вартості розмови в Direct, грн |
| `freq_yellow` / `freq_red` | `2` / `3` | частота акаунта: від цього значення 🟡 / 🔴 |
| `trend_band_pct` | `5` | поріг для стрілок ↗ ↘ (±%) |
| `color_band_pct` | `10` | поріг для 🟢 🟡 🔴 порівняно із середнім (±%) |
| `pixel_crm_diff_yellow_pct` / `_red_pct` | `20` / `40` | розбіжність піксель vs CRM |
| `utm_missing_warn_pct` | `30` | частка замовлень сайту без UTM, від якої 🟡 |

> Реальні цифри далекі від цілей (розмова ≈ 250 грн, CPA ≈ 800 грн), тому світлофор майже завжди червоний. Якщо хочете, підлаштуйте цілі під реальність.

### Нове налаштування (додавати не обов'язково)

| Рядок (key) | Дефолт | Що робить |
|---|---|---|
| `keycrm_count_zero_total_orders` | `FALSE` | замовлення з сумою 0 (заміни, подарунки) не рахуються продажем. Якщо потрібно рахувати, додайте внизу листа рядок: A = `keycrm_count_zero_total_orders`, B = `TRUE` |

Після зміни `keycrm_*` налаштувань запустіть у Apps Script функцію **`reclassifyOrders`**, щоб перерахувати вже збережені замовлення.

## Частина 3. Лист «Правила_UTM»

Змінювати нічого не треба. Це правила, за якими замовлення відносяться до каналів (Meta, Google, email тощо). Якщо таргетолог введе нову назву джерела UTM, додайте рядок за зразком існуючих, а потім запустіть `reclassifyOrders`.

## Частина 4. Після оновлення коду (порядок запуску)

У Apps Script вибирайте функцію зі списку зверху й натискайте «Запустити»:

1. `runTests`: у Node 130 тестів, в Apps Script менше (частина перевірок працює лише в Node). Головне: «провалено 0»
2. `installTrigger`: створює тригери о 9:00 (звіт) і 11:00, 14:00 (повторні спроби)
3. `backfill30`: перезавантажує 30 днів Meta й KeyCRM
4. `reclassifyOrders`: перераховує канали й статуси
5. `rebuildLast7Reports`: оновлює тексти звітів за 7 днів у листі (у Telegram нічого не надсилає)

## Частина 5. Що перевіряти раз на кілька днів

- Лист **Лог**: рядки зі словом `ERROR` або `WARN`. Якщо їх нема, усе добре.
- У Лозі після кожного запуску є рядок «Часові зони акаунтів». Якщо там порожньо або не `Europe/Kyiv`, напишіть мені.
- Звіт у Telegram має приходити щодня близько 9:00.
